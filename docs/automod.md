# AutoMod

All rules start off. Server administrators opt in with `/automod`; the caller
and bot need **Manage Server**. Custom message enforcement additionally needs
**Manage Messages** in the affected channels. Choose a staff alert channel the
caller can view and the bot can view and send to. Custom alerts contain member/channel
IDs, message links, and action outcomes, not copies of message bodies.

## Discord-native presets

`/automod native preset:keywords mode:observe alert_channel:#staff keywords:bad phrase,scam*`
creates an alert-only Discord rule. Change to `mode:enforce` to block and alert.
`preset:mentions` takes a `mention_limit` (default 5); `preset:spam` uses Discord's
generic spam classification. `mode:off` disables the preset; `/automod remove`
deletes it. Only rules whose creator is this bot and whose names match Radon's
preset names are modified. Other bots' and administrators' rules are preserved.

Optional `exempt_roles` and `exempt_channels` accept IDs separated by spaces or
commas (Discord limits: 20 roles, 50 channels). Existing native exemptions,
keywords, and mention thresholds are preserved when omitted on an update.
Pass `none` to clear an exemption list. Keywords support Discord wildcards;
regular expressions and automatic timeout actions are not exposed here.

Discord enforces native rules independently of the bot's gateway connection.
Native alerts are generated by Discord and can include matching message content.
No privileged Message Content intent is required to manage these presets.
Discord permits six keyword rules and one rule each for generic spam and mention
spam per guild. A different existing rule may already consume that quota; Radon
reports the failure and does not replace it. Native AutoMod has Discord-defined
administrator/Manage Server exemptions and matching behavior.

## Custom message rules

Custom inspection is disabled unless the operator enables **Message Content** in
the Developer Portal and sets `RADON_AUTOMOD_CONTENT_ENABLED=true` before restart.
Verified bots may need approval from Discord for this privileged intent. The
configuration command refuses to enable these rules if the running client does
not request the intent. Neither optional privileged intent is enabled by default.

- `/automod flood mode:observe alert_channel:#staff threshold:6 duplicates:3 window:10`
  counts messages and repeated normalized text per member across the guild.
  Distinct-channel repeats are identified in alerts. Edits do not count as new
  messages. Enforce deletes each matching message; it does not bulk-delete older
  messages or timeout a member.
- `/automod links mode:observe alert_channel:#staff blocked_domains:example.com block_invites:true`
  detects HTTP(S) URLs and Discord invite links. A blocked domain includes its
  subdomains but does not match lookalike suffixes. `allowed_domains` takes
  priority over blocked domains and invite detection. Lists replace the old list;
  `allowed_invites` permits specific case-sensitive invite codes (for example,
  `AbC123`) on canonical Discord invite hosts without allowing every Discord
  invite. Lookalike hosts cannot use those exceptions. Codes are stored as
  entered and are not looked up externally. Existing configurations default to
  an empty approved-invite list.
  use `none` to clear one. No remote reputation checks or redirect following occur.
  Message edits are checked too.
- `/automod exemptions roles:... channels:...` replaces exemptions for custom
  message rules. Use `none` for empty lists. Thread-parent channel exemptions are
  honored. Bots, webhooks, server owners, and members with Manage Messages are
  excluded. Raid detection counts non-bot joins and is separate from message
  exemptions.

`mode:observe` only alerts. `mode:enforce` deletes matching messages and reports
whether deletion actually succeeded. Alerts are limited to one per member per
30 seconds; deletion is not suppressed by that alert limit. Deleted-message
links naturally stop opening. Detection windows retain SHA-256 fingerprints,
IDs, and timestamps, not message bodies. They expire after inactivity and have
fixed key/event ceilings. Configurations are cached for 15 seconds and invalidated
immediately in the configuring process. On multiple processes other workers see
configuration updates within that cache period. Detection windows are local to
each process; a guild must be handled by one gateway worker/shard for accurate
thresholds. Bot restarts reset detection windows, but preserve configuration.

## Join-burst response

Enable **Server Members** in the Developer Portal and set
`RADON_AUTOMOD_MEMBERS_ENABLED=true` before restart to opt into join events.
`/automod raid mode:observe alert_channel:#staff threshold:10 window:10` reports
bursts without restricting members. Observe first and tune for legitimate events.

`mode:enforce duration:600` temporarily changes guild verification to **Highest**
when the threshold is reached. This requires phone verification for affected
unverified members; existing members with roles are unaffected. It does not ban,
kick, quarantine, or remove roles. An already-Highest setting is left unchanged.
Further joins do not extend an active restriction. Setting raid mode to `off` or
`observe` restores an active restriction early.

The previous verification level and deadline are persisted **before** the Discord
request. Unknown request outcomes retain that recovery record. A recovery worker
runs on startup and every 15 seconds; a missed deadline while offline is processed
when the bot reconnects. Expired work is claimed using an atomic MongoDB
`findAndModify` lease shared by restriction application and restoration, not Prisma's
non-atomic MongoDB `updateMany` compare-and-set pattern. Five-minute leases renew
every minute while Discord requests are pending; server-time token/deadline checks
guard each action and completion. Applying work cannot be concurrently restored.
A disable request or expired deadline observed while applying is reconciled before
releasing the lease. Pending disabled rules are also eligible for early recovery.
Recovery queries exclude null deadlines, active/backoff leases, and other shards
before ordering and limiting results. Failed recovery retains the snapshot and
backs off for one minute; uncertain application outcomes defer automatic recovery
for five minutes. A terminated worker's lease expires after at most five minutes.
Discord has no fencing-token API, so a process that loses database access during
an in-flight Discord request cannot cancel that already-sent request; the snapshot
is retained for reconciliation rather than treated as completed.
If verification was changed to a level other than Highest
in the meantime, Radon preserves that change and clears its pending restoration.
An administrator reapplying Highest is indistinguishable from Radon's original
restriction; turn raid mode off before making a permanent Highest change.

## Storage and validation

The additive `automodConfig` collection contains per-guild configuration and raid
recovery state. Existing guild documents do not need migration. Apply the schema
using the deployment's normal reviewed Prisma MongoDB schema/index workflow;
do not run a production `db push` just to execute tests. Generate Prisma Client
before typechecking or deploying this change.

Offline validation: `bun test` and `bun run typecheck`. Optional MongoDB integration
checks require `RADON_TEST_MONGO_URL` and deliberately reject all destinations
except `mongodb://127.0.0.1:27028/radon_test_*` or the same localhost address.
They create and remove only uniquely named test configuration records.

A staging guild smoke test should verify native rule quota/permissions, alert
routing, observation before enforcement, a link edit, and verification restoration
after restart. These tests do not require real Discord or production database
credentials.
